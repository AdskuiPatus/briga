# madrigal-lab

Локальный инструмент исследования недокументированного бинарного обмена
поверх TCP по записям PCAP/PCAPNG (кейс «Лаборатория протоколов МАДРИГАЛ»).

## Статус

Этапы 1–5 — готовы: ядро данных, веб-интерфейс исследования,
декларативные интерпретации с проверкой гипотез, проверка по корпусу
записей с контрпримерами и сводкой, переносимый проект, отчёт
исследователя и golden-примеры повторного применения.

| Возможность | Требование | Статус |
|---|---|---|

| Порядок байтов по TCP sequence numbers независимо от порядка пакетов | R1, 7.3 | ✅ |

## Запуск

Требования: Python 3.12+.

```bash
python -m pip install -r requirements.txt      # зависимости интерфейса
```

### Веб-интерфейс (основной сценарий)

```bash
python -m madrigal serve --open                # http://127.0.0.1:8000
```

В интерфейсе: путь к записи (кнопка «Обзор…») → список TCP-сессий → вкладки
направлений → hex-поток. Клик по байту — выделение, Shift+клик — диапазон;
внизу показываются hex/ascii и пакеты-источники (клик открывает пакет с
заголовками и подсвеченным payload). Поиск ASCII/HEX с переходами по
совпадениям; вкладка «Сравнение» — побайтовое сравнение двух примеров;
вкладка «Интерпретация» — редактор схемы, применение к сессии/записи,
результаты разбора (клик по сообщению — переход к его байтам), проверка
гипотез и проверка корпуса; результаты, полученные по изменившейся схеме,
приглушаются с предупреждением об устаревании.

### CLI

```bash
python -m madrigal info examples/demo.pcapng
python -m madrigal stream examples/demo.pcapng 0 a2b
python -m madrigal packet examples/demo.pcapng 4
python -m madrigal apply examples/demo.pcapng --schema examples/demo-protocol.yaml --out result.json
python -m madrigal verify examples/demo-corpus.yaml --out report.json
python -m madrigal stale report.json
python -m madrigal project check .
python -m madrigal report . --md reports/research-report.md
python -m madrigal golden
```

`apply` применяет схему ко всем сессиям (или `--session N`), печатает сводку
по направлениям и результаты проверки гипотез, пишет машиночитаемый JSON.
Код выхода 3 — найдены контрпримеры (гипотеза опровергнута данными).
`verify` прогоняет корпус записей с ожиданиями (R4), код выхода 4 —
ожидания корпуса не выполнились. `stale` пересчитывает контрольные суммы
отчёта, код выхода 5 — отчёт устарел. `project` — переносимый проект
(R5), `report` — отчёт исследователя (R6), `golden` — повторное
применение интерпретации с ожидаемыми результатами (R6), код выхода 4 —
расхождение с принятыми ожиданиями.

## Схема интерпретации (R3)

Схема — YAML или JSON, правила и гипотезы разделены (пример:
`examples/demo-protocol.yaml`):

```yaml
version: 1
name: demo-protocol
scope: {directions: [a2b, b2a]}        # область действия
framing:                               # как делить поток на сообщения
  magic: "AA 55"
  header: 5
  length: {offset: 3, type: u16le, includes: payload}
  min: 5
  max: 65536
messages:                              # правила: применяются программно
  - id: set_value
    direction: b2a                     # a2b | b2a | any
    when: [{offset: 2, type: u8, eq: 2}]   # eq | in | bytes
    fields:
      - {name: value, offset: 5, type: u16le}
hypotheses:                            # предположения: основания + проверка
  - id: h-echo
    statement: "ответ подтверждает установленное значение"
    basis: ["запись: действие «задать 21» → в ответе 21"]
    status: proposed                   # proposed | checked | refuted | refined
    check:                             # опциональная механическая проверка
      pairs:
        a: {message: set_value, field: value}
        b: {message: set_ack, field: value}
      expect: equal
```

Поведение при применении: первое подошедшее правило побеждает; сообщение без
подходящего правила остаётся `id=null` (неохват видим); байт в пропуске не
подменяется — сообщение `partial`, поле `known=false`; результаты проверки
гипотез — `pass / fail (с контрпримерами) / incomplete / not_applicable /
not_checked`, статус `checked` выставляется только при полном проходе.

## Корпус проверки (R4)

Корпус — манифест с записями и ожиданиями исследователя (пример:
`examples/demo-corpus.yaml`; пути относительно манифеста):

```yaml
version: 1
name: demo-corpus
schema: demo-protocol.yaml
files:
  - path: demo_counterexample.pcapng
    note: контрпример — ответ содержит чужое значение
    expect:
      sessions: 1
      directions:
        b2a: {matched: {set_value: 2}, unmatched: 0}
        a2b: {matched: {set_ack: 2}}
      hypotheses: {h-echo: fail}       # ожидаем опровержение данными
```

Правила сверки: числа — строго; `matched` — только перечисленные типы;
`hypotheses` — результат механической проверки. Прогон
(`verify`, API `POST /api/verify`, кнопка «Проверить корпус» в UI) даёт
отчёт с пятью группами находок:

| Группа | Что попадает |
|---|---|
| нарушения | ожидания не выполнились; гипотеза опровергнута данными (с контрпримерами и пакетами) |
| неохват | неопознанные сообщения, байты вне сообщений, ошибки фрейминга |
| неоднозначности | конфликтующие перекрытия восстановления (политика first-seen) |
| неприменимые | вне области действия схемы; проверки без примеров сообщений |
| неизвестные | пропуски, частичные сообщения, неполные пары, соединения без рукопожатия |

Отчёт (`--out report.json`) штампуется: версия инструмента, время, sha256
манифеста, схемы и каждой записи. `stale report.json` пересчитывает суммы и
перечисляет причины устаревания — устаревший результат отличим от
актуального и в CLI, и в UI (приглушение + предупреждение). Живое изменение
интерпретации: в UI «Проверить корпус» прогоняет записи по активной схеме
редактора, в CLI — `verify --schema другой.yaml`; расхождения с новой
схемой становятся видимыми сразу же.

## Переносимый проект (R5)

Исследование сохраняется как каталог с манифестом `project.yaml` (пример —
корень этого репозитория). Манифест связывает записи, интерпретации,
корпуса, результаты проверок и наблюдения; **все пути относительные**
(POSIX-разделители `/`), абсолютные пути и выход за каталог проекта
отклоняются при загрузке:

```yaml
version: 1
name: madrigal-demo
description: исследование протокола демо-стенда
requires: {python: ">=3.12", packages: [pyyaml>=6.0]}   # условия воспроизведения
settings: {overlap_policy: first-seen, directions: [a2b, b2a]}
recordings:
  - {path: examples/demo.pcapng, sha256: <hex>, note: эталон}
schemas:
  - {path: examples/demo-protocol.yaml, sha256: <hex>}
corpora:
  - {path: examples/demo-corpus.yaml, sha256: <hex>}
results:
  - {path: reports/demo-corpus-verify.json, kind: corpus-verify}
observations:                          # наблюдания со связями к источникам
  - text: "ответ подтверждает значение"
    source: {file: examples/demo.pcapng, session: 0, direction: a2b,
             offset: 9, packets: [8, 9]}
```

```bash
python -m madrigal project init DIR          # создать манифест
python -m madrigal project add DIR recording|schema|corpus|result FILE
python -m madrigal project observe DIR "текст" --file F --session N ...
python -m madrigal project check DIR         # после переноса: целостность
```

`project check` после копирования каталога в другой каталог/машину сверяет
контрольные суммы записей, схем и корпусов, а зарегистрированные отчёты
проверяет механикой `stale` (поиск манифеста — относительно проекта, без
прежних абсолютных путей). Устаревшие результаты отличимы: check код 5 и
пометка `STALE`/`УСТАРЕЛ`. Файл вне каталога проекта добавить нельзя —
исследование переносится целиком.

## Отчёт исследователя и повторное применение (R6)

```bash
python -m madrigal report . --md reports/research-report.md --json reports/research-report.json
```

Читаемый отчёт (Markdown) и его машиночитаемая форма (JSON) собираются из
проекта: исследованные записи с контрольными суммами; интерпретации —
область применимости, распознаваемые сообщения, таблица гипотез
(утверждение, основания, статус, тип проверки); проверенные примеры —
итоги прогонов корпуса со сводкой пяти групп; контрпримеры —
опровергнутые данными гипотезы с привязкой к пакетам; наблюдения
исследователя со связями «файл/сессия/направление/смещение/пакеты»;
ограничения области применимости; открытые вопросы (непроверяемые
механически предположения, неохват, неизвестные, неоднозначности, а также
устаревшие отчёты); документированные команды повторного применения.

### Golden-примеры: входы + ожидаемые результаты

```bash
python -m madrigal golden                        # сверить: код 4 при расхождении
python -m madrigal golden --update               # принять текущие факты как ожидания
```

`examples/golden.yaml` — комплект воспроизводимых случаев: фиксированные
входы (запись + схема, либо корпус) и нормализованные ожидаемые
результаты (sha256 входов, счётчики сообщений по направлениям, список
сообщений, результаты проверки гипотез). Прогон сверяет факт с ожиданием
по путям — повторное применение даёт механически проверяемые
согласованные результаты. `--update` после уточнения интерпретации —
явное документирование изменения ожиданий.

## Политика обработки дефектов (зафиксирована, воспроизводима)

* повторная передача с совпадающими байтами → байты не дублируются,
  пакет остаётся в источнике, факт фиксируется в `retransmissions`;
* перекрытие с различающимися байтами → остаются байты **первого** пакета в
  записи (first-seen), альтернатива сохраняется в `ambiguities` вместе с
  обоими packet id;
* пропуск → участок помечен как неизвестный (`??` в hexdump), `to_bytes()`
  отказывается его подменять.
